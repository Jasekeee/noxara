# NOXARA: independent security and token-economy audit (A)

Auditor: fresh, independent, read-only. Date: 2026-11-14, ~13:30–14:10 UTC. Mainnet block ~224,522,000.
Scope: `noxara.near` (game + NEP-141 NOX + NEP-245 shares), `relay.noxara.near` relayer/match server (Railway), economy design and sim.
Method: read the source (`contracts/royale/src/*.rs`, `relayer/src/*.ts`, docs), ran read-only RPC views (free.rpc.fastnear.com) and nearblocks queries, sent 3 polite GET/OPTIONS requests to Railway, ran `cargo test --lib` and `node scripts/econ-sim-v2.ts` locally. I sent no transactions, played no live matches, and read no secret or .env files.

## Scores
| Axis | Score | One-line reason |
|---|---|---|
| **Security** | **7 / 10** | The contract is careful: keyless NPCs, private init, 1-yocto on value-moving share calls, game wallets can't receive transfers, two-step owner handover, the deployed hash matches the source, no secrets in git. Points lost: settlement trusts one hot key on Railway, the contract FAK is kept and the owner account has 26 FAKs, the guest and subsidy budgets can be drained by anyone at no cost, and the season-end date in the contract differs from the docs. |
| **Economy design** | **7 / 10** | A closed loop with no mint after genesis, a public EMA House rule with a deflation brake, progressive upkeep and entry fees, bankruptcy and rookies, dividends paid only from profit, and a sim that is reproducible and passes. Points lost: the whole balance assumes the human wins 8% of matches. The seed is public and the sim is deterministic, so a scripted client can win far more often, and welcome-credit wins pay out real NOX that sybil accounts can farm. At a 60% human win rate the sim's own checks FAIL. |

## What is solid
- **Deployed code = the audited source**: the on-chain code_hash equals the local wasm sha256, which records the current source hash **[verified]**.
- **NPCs are truly keyless** (house + 9 bots have 0 access keys), and `refuse_game_wallet` blocks transfers into any game wallet, including `ft_transfer_call` refund games **[verified]**.
- **Init can't be front-run** (`#[init] #[private]`, deploy+new in one tx); the owner handover is two-step; the teardown beneficiary is fixed and time-locked **[verified]**.
- **No mint after genesis** is enforced in code and holds on mainnet (minted = 2,900) **[verified]**; rewards come only from the House above its floor.
- **Value-moving share actions need a full-access signature** (1 yocto on `list_shares`, `buy_listing`, `mt_transfer`, `ft_transfer`); there is no `mt_transfer_call`, so no callback class **[verified]**.
- **Relayer hygiene**: the signature and the access-key owner are checked before any spend; single action, zero deposit, a method allow-list with per-method gas caps; right-most XFF only behind a trusted proxy; body-size limits; CORS is an allow-list; budgets persist atomically; the policy refuses the relayer and contract as sender **[verified]**.
- **Guest isolation**: guests earn 0, can't hold shares, have FC keys restricted to `start_match,sweep_match`, and are created by the contract (`create_guest`) so Railway needs no contract key **[verified]**.
- **Next-block seed** via a `resolve_start` self-callback; free/paid pools are separated; lazy expiry of free matches; bounded loops (teardown batches, prune caps, recent 50) **[verified]**.
- **No secrets in git history** (0 key/token patterns in 3.8 MB of patches) **[verified]**.
- **The economy is well engineered for honest play**: EMA House rule, deflation brake, progressive upkeep and entries, rookie protection, profit-only dividends with an O(1) accumulator, capped login pools; 115 unit tests and a 20×10k sim all pass **[verified]**.
